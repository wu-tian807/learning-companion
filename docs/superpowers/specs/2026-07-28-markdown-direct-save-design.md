# Markdown 普通编辑与直接保存设计

> 日期：2026-07-28
>
> 状态：已确认，待实施
>
> 本文覆盖《Markdown 与 PDF Workbench 设计》中关于 WYSIWYG 往返检查、只读授权和规范化差异确认的既有设计。

## 背景

Vditor 会把 Markdown 源码解析为可视化文档，并在用户编辑后重新序列化整份 Markdown。现有实现把初始化时的源码差异视为风险，因此将编辑器设为只读、显示授权提示，并在保存时再次要求用户检查差异。

这套流程虽然保守，但不符合记事本或 VS Code 一类编辑器的使用习惯：

- 打开文档后应当可以直接阅读和编辑；
- 用户实际输入后才应进入“未保存”状态；
- 点击保存按钮或按下 `Ctrl/Cmd + S` 已经是明确的写入授权；
- 未主动保存的修改应由恢复缓存保护，而不是通过只读提示阻止编辑。

Vditor 的只读实现还会给正文设置 `opacity: 0.3`，导致深色背景下的正文难以阅读。

## 交互决策

Markdown Workbench 采用普通编辑器语义：

1. WYSIWYG 初始化完成后立即可编辑，不进行源码往返授权。
2. 不显示“无法无损往返”的底部提示框。
3. 初始化、重新挂载和单纯切换编辑模式不会把文档标记为已修改。
4. 只有用户产生真实输入后，Workbench 才更新 `workingBuffer`、显示“未保存”并写入恢复缓存。
5. 点击保存按钮或按下 `Ctrl/Cmd + S` 时，直接保存当前 `workingBuffer`，不再弹出源码差异确认。
6. 保存成功后更新磁盘基线并清除恢复缓存；保存失败时保留编辑内容、未保存状态和恢复缓存。
7. 外部文件 revision 冲突检测继续保留，防止覆盖其他程序在磁盘上产生的新修改。

用户没有执行保存时，磁盘文件保持不变。应用异常退出或离开 Project 后，再次打开文档时仍可通过现有恢复流程找回未保存内容。

## 状态与命令收敛

源码模式和 WYSIWYG 模式共享同一个 `workingBuffer`，但各自保留编辑器视图状态。

删除不再具有业务意义的规范化确认状态和命令：

- `MarkdownNormalizationState`；
- `normalizationState`；
- `markdown:save-normalized`；
- `MARKDOWN_NORMALIZATION_REVIEW_REQUIRED`；
- Renderer 的差异确认弹窗；
- 仅用于该弹窗的 `diff-match-patch` 依赖。

统一保留一个 `markdown:save` 命令。Main Provider 仍负责 revision 校验、编码、行尾、原子写入、保存失败后的恢复快照调度，以及保存成功后的恢复数据清理。

Vditor 初始化期间产生的内部转换事件继续由 `MarkdownEditorInputGate` 屏蔽。这样即使 Vditor 的初始序列化结果与磁盘源码不完全一致，只要用户没有输入，`workingBuffer` 就仍然保持原始源码。

## 恢复缓存

沿用现有记事本式恢复模型：

```text
用户输入
  -> Renderer 立即同步 workingBuffer 到 Main
  -> Main debounce 持久化恢复快照
  -> 保存成功后清除恢复快照
```

Session 关闭前必须等待命令队列并强制落盘最后一份恢复快照。恢复快照基于旧 revision 时继续提示磁盘文件已经变化，不能自动覆盖新版本。

## 视觉设计

Markdown 内容区保持当前深色背景 `#1b2027`，正文使用独立、明确的高对比度颜色，不依赖 Vditor 默认主题的低优先级颜色：

- 普通正文：`#dce4ee`；
- 标题和强调文字：`#f8fafc`；
- 次要文字、引用：`#b9c4d1`；
- 链接：`#93c5fd`；
- 行内代码和代码块正文：`#e2e8f0`。

Markdown Workbench 使用作用域 CSS 覆盖 Vditor 内容主题，避免影响其他 Workbench。正文始终保持 `opacity: 1`；加载态和真正不可用的控件可以降低透明度，但文档内容本身不能通过透明度表达只读或错误状态。

## 错误处理

- 保存失败：显示统一错误弹窗，保留未保存内容和恢复快照。
- revision 冲突：阻止写入并提示重新打开或另存处理，不静默覆盖。
- WYSIWYG 初始化失败：保留现有“切换到源码模式”的降级入口。
- 恢复快照失败：记录并反馈错误，但不清空 Renderer 中的当前内容。

## 验证

实现后至少验证：

- 打开包含表格、LaTeX、Mermaid 和 HTML 的 Markdown 时不出现授权提示框；
- 打开后不输入，文档保持“已保存”，关闭不会改写磁盘文件；
- 第一次真实输入后显示“未保存”并产生恢复快照；
- 保存按钮和 `Ctrl/Cmd + S` 均直接写入，不出现差异确认；
- 保存成功后恢复快照被清除；
- 保存失败或 revision 冲突后编辑内容仍在；
- WYSIWYG 正文、标题、引用、链接和代码在深色背景下清晰可读；
- 源码模式、编码、行尾和视图状态功能不受影响。
