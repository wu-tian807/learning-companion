# Asset 导入入口与来源标识设计

> 状态：已实施
>
> 日期：2026-07-30

## 1. 目标

在不增加普通用户操作负担的前提下，为少数需要保留原文件位置的用户开放
“链接外部文件”，同时让外部来源的 Asset 在列表中可以被快速识别。

## 2. 导入交互

左侧 Asset 面板使用分裂按钮：

- 主按钮仍显示“添加资料”，点击后选择本地文件，并以 `copy` 模式导入；
- 右侧小箭头打开菜单，菜单目前只提供“链接外部文件”；
- 菜单项附带说明：“不复制文件，移动原文件后可能失效”；
- 选择“链接外部文件”后使用同一个多文件选择器，以 `link` 模式批量添加；
- 每次菜单选择只影响本次导入，不保存为用户偏好；
- 拖拽文件始终使用 `copy`，不弹出额外选择。

普通用户只有一条突出的默认路径；外部链接属于低频高级入口，不和默认导入争夺
视觉层级。

## 3. 来源徽标

Asset 列表根据 `contentRef` 判断来源，在文件信息第二行显示低对比度的小圆角徽标：

- `{ kind: "local-file", base: "project-workspace" }`：不显示徽标；
- `{ kind: "local-file", base: "absolute" }`：显示“外部”；
- 未来增加网络 ContentRef 时：显示“网络”。

来源到文案的映射集中在一个小型纯函数中，列表组件不直接堆叠各类
`contentRef` 判断。当前只实现已有的本地文件类型，不提前增加网络协议。

## 4. 数据流

```text
主按钮 / 拖拽
  -> addLocalAssets({ projectId, paths, mode: "copy" })
  -> 外部文件复制到 Workspace/assets/imported

小箭头 -> 链接外部文件
  -> addLocalAssets({ projectId, paths, mode: "link" })
  -> 记录 absolute ContentRef，不复制原文件
```

批量导入响应、错误反馈、当前 Project 校验和 Renderer 全量快照替换沿用现有流程。
选择文件期间切换 Project 时，Main 仍根据请求携带的 `projectId` 拒绝错误上下文。

## 5. 错误与边界

- 用户取消文件选择时不显示错误；
- `link` 文件不可访问或导入失败时，沿用统一错误弹窗和批量失败摘要；
- 工作区内文件即使通过“链接外部文件”入口选择，也由
  `ProjectWorkspaceManager.classifyLocalFile` 归一化为工作区相对引用，不错误标记为
  “外部”；
- 删除外部 Asset 只删除应用记录，不删除原文件；
- 外部文件移动或删除后，现有 Availability、刷新和重新定位流程继续生效。

## 6. 测试与验收

- IPC 契约接受并校验可选的 `copy | link` 模式；
- 批量导入把模式传递给每次 `AssetService.addLocalFile`；
- 主按钮与拖拽发送 `copy`，下拉菜单发送 `link`；
- 工作区相对引用不显示徽标，绝对路径引用显示“外部”；
- 键盘焦点、菜单外点击关闭和禁用状态与现有菜单行为一致；
- `pnpm check` 通过，并在 Electron 中检查分裂按钮、菜单位置和徽标可读性。
