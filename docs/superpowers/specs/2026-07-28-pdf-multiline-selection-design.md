# PDF 多行文字选区修复设计

## 问题

PDF.js 的浏览器选区文本会依据视觉行布局插入空格或换行，而当前 Anchor 映射使用 Text Layer 的 DOM Range 文本建立字符偏移。两者包含的非空白字符相同，但空白分隔可能不同。

当前校验会把空格和换行统一成一个空格，因此无法等价处理“`第一行\n第二行`”与“`第一行第二行`”。校验失败后 PDF 工作台清空选区，右侧上下文表现为未选择。

## 方案

新增一个仅供映射校验使用的文本等价规则：

1. 对两侧文本执行 NFC Unicode 归一化。
2. 移除全部 Unicode 空白字符。
3. 仅当剩余字符完全相同时，才接受选区映射。

选区是否为空仍使用现有规范化逻辑判断。右侧展示、复制以及 Anchor 的 `quote.exact` 继续保留 `Selection.toString()` 返回的原始文本，不修改用户看见的空格和换行。

该规则不会忽略标点、字母、数字或汉字差异。任何非空白字符不一致仍会拒绝映射并清空上下文。

## 模块边界

- `pdf-viewer-adapter.ts`：提供 PDF 选区与索引文本的等价判断，并在创建 Snapshot 时使用。
- `pdf-viewer-adapter.test.ts`：覆盖单行、多行换行差异、词间空格差异和真实字符不一致。
- Generation Center 无需修改，它继续消费统一的 `WorkbenchSelectionSnapshot`。

## 验证

- 单页单行选择仍可生成 Anchor。
- 单页跨多行选择能够显示在右侧上下文。
- 连续阅读模式下跨页选择保持有效。
- 非空白字符不同的错误映射仍被拒绝。
- 运行完整类型检查、Lint 和测试。
