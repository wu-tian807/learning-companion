# 工作台右键菜单可视区域定位设计

## 目标

右键菜单始终完整位于当前 Electron 页面可见区域内。菜单靠近窗口底部或右侧打开时自动向上或向左移动；窗口高度不足以容纳完整菜单时，菜单自身允许纵向滚动。

该改动统一作用于 `WorkbenchContextMenuHost` 承载的所有工作台右键菜单，不在纯文本、Markdown 等具体工作台内分别实现。

## 现状与原因

当前定位函数使用固定的 `240 × 340` 菜单尺寸计算坐标。菜单的实际高度会随贡献项和分组变化，因此固定高度小于真实高度时，菜单底部会越过可见区域。

## 设计

1. 首次渲染时先使用点击坐标作为候选位置。
2. 通过菜单根节点的真实布局尺寸重新计算坐标。
3. 优先使用 `window.visualViewport` 的宽、高和偏移量描述实际可见区域；不可用时回退到 `window.innerWidth` 和 `window.innerHeight`。
4. 菜单与可见区域四边保留 8px 间距：
   - 右侧空间不足时向左移动。
   - 底部空间不足时向上移动。
   - 点击坐标本身在区域外时也夹取到合法范围。
5. 菜单最大高度限制为可见区域高度减去上下间距，并启用纵向滚动。该滚动由菜单自身消费，不传递给编辑器，也不关闭菜单。
6. 页面滚动、窗口尺寸变化或 `visualViewport` 变化时关闭菜单，避免菜单与原始点击位置脱离。

## 模块边界

- `context-menu-position.ts`：只负责基于候选坐标、真实菜单尺寸和可视区域计算最终位置，保持为可单元测试的纯函数。
- `WorkbenchContextMenuHost.tsx`：测量 DOM、监听可视区域变化，并把尺寸交给定位函数。
- `WorkbenchMenu.tsx`：提供最大高度与内部溢出滚动的通用样式，不负责坐标计算。

## 验证

- 单元测试覆盖右下角、左上角、尺寸变化和菜单高于可视区域。
- 运行完整类型检查与测试。
- 在 Electron 中分别于页面中部、右下角和低高度窗口打开纯文本及 Markdown 右键菜单，确认所有操作可见；超高菜单可以内部滚动。
