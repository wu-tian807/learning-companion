# 声音克隆多模型赛马与后缀调度验证

> 该 Demo 已完成选型使命。主程序首版选择 VoxCPM2，F5-TTS 与 VoxCPM1.5 仅保留为备选；大型 `.runtime` / `.models` 数据已清理。若要重跑赛马，需要重新执行下方安装命令。

正式产品边界与选型结论见[视频声音克隆设计](../../docs/superpowers/specs/2026-08-28-video-dubbing-design.md)。

这是一个与主应用完全隔离的 Demo，验证两件事：

1. 当本地声音克隆速度慢于或接近播放速度时，如何仍给用户一段稳定、连续的配音体验。
2. VoxCPM1.5、VoxCPM2 与 F5-TTS v1 在同一输入下的 one-shot 质量、长程稳定、RTF 和显存成本。

## 赛马候选

- **VoxCPM1.5：** 参考音频及其准确转写，约 1.95 GB；视频字幕可提供参考转写。
- **VoxCPM2：** 只使用参考音频，约 4.96 GB；用于验证免转写 one-shot 的质量与成本。
- **F5-TTS v1 Base：** 参考音频及其准确转写，主模型约 1.35 GB；作为独立架构对照。
- **本轮验证运行时：** OpenBMB 官方 Python 实现 + PyTorch CUDA。
- **产品运行时尚未锁死：** 如果质量成立，再比较官方 Python 的可分发成本与 GGUF/C++ 运行时；Demo 不把二者混为一个决定。
- **CPU 策略：** 第一版禁用完整视频声音克隆，不让用户等待数倍于视频时长的处理。

三者使用同一段官方参考音频、同一组中英文短句与 64 段、4 轮中英交替长程输入，不用不同输入制造虚假的模型差异。

## 后缀相遇算法

配音块固定从视频结尾向前生成。设：

- `D`：视频剩余媒体时长；
- `r`：实测 RTF；
- `v`：播放倍速；
- `L`：尚未消耗的模型冷启动时间。

生成速度是 `1 / r` 个媒体秒 / 墙钟秒。忽略已经完成的后缀时，播放头与生成头的预计相遇时间为：

```text
t = (D + (1 / r) * L) / (v + 1 / r)
```

实际调度还会代入当前播放位置和已生成后缀起点。预测只用于告诉用户“预计何时可切换”；播放器真正切换的唯一依据是已经落盘并连续覆盖到结尾的音频范围。

## 运行交互原型

```powershell
pnpm test
pnpm start
```

打开 `http://127.0.0.1:4178`。时间轴含三种信息：

- 紫色：播放进度；
- 白色：实际已经生成、并且能连续播放到结尾的克隆后缀；
- 黄色虚线：根据当前 RTF 预测的首次切换点。

拖动播放头不会清空已有白色后缀，只会重新计算相遇位置。

## 上传真实中 / 英文视频

完成字幕组件与三模型安装，并在 Codex 登录 ChatGPT 账号后，运行 `pnpm start` 并打开：

```text
http://127.0.0.1:4178/web/video-demo.html
```

实验台只接收本机视频，并按以下真实链路执行：

```text
中文或英文视频
  → 已安装的 Whisper CUDA 自动识别语言并转写
  → UVR-MDX-NET-Inst_HQ_4 分离纯人声与背景轨
  → Codex LLM 在一个连续 Thread 中完成上下文中英互译
  → 只在真实 Cue 边界内合并过短字幕，并生成独立朗读文本
  → 从纯人声轨自动截取 one-shot 参考人声
  → F5-TTS / VoxCPM1.5 / VoxCPM2 串行占用 GPU
  → 每个模型先生成最右端 Cue 并实测时间轴 RTF
  → 从结尾向前扩展已经落盘的连续配音后缀
```

- 英文原声生成简体中文配音，中文原声生成英语配音；暂不接受其他语言。
- 默认翻译模型为 `gpt-5.6-luna`、`low` 思考力度；可分别用 `LC_DEMO_TRANSLATION_MODEL` 与 `LC_DEMO_TRANSLATION_REASONING` 覆盖。
- 一段视频尽量一次翻译；输入过长时才分段，并用同一个 Codex Thread 继续，保持人名、术语与上下文一致。
- LLM 只能返回 Cue ID 与译文。时间戳始终沿用 Whisper 的真实边界，模型不能改写时间。
- 过短译文只会在相邻间隔不超过 700 ms、合并后不超过 8 秒且字幕长度不过载时合并；无法安全合并时保留原 Cue。
- 中文配音会把数字转换为自然朗读形式，但画面字幕仍保留阿拉伯数字。
- 三模型不会并发抢占显存，因此 RTF 可以直接比较。
- 最右端探针就是第一段正式产物，不做浪费性的假预热。
- 调度 RTF 使用“生成墙钟时间 / 字幕时间轴时长”；原始语音时长与首块延迟另行展示。
- 每个 Cue 在落盘后用 FFmpeg 做无变调时长适配，播放器只在该 Cue 真正可用时切换声音。
- 连续生成后缀之外播放完整原声；后缀之内持续播放背景轨，并只在对应 Cue 叠加克隆人声。
- 本机 RTX 4090 D 的 30 秒 UVR 探针耗时 1.01 秒、RTF 0.034；这是当前机器实测，不作为其他设备承诺。
- 实验文件、Python 缓存与模型缓存只写入 Demo 的 `.runtime` / `.models`；短路径构建临时目录会在任务结束后删除。

可用 `?session=<实验 ID>` 直接恢复某次结果，便于三模型反复试听。

## 安装并运行真实 CUDA 验证

安装脚本创建 Demo 私有 Python 环境，不修改系统 Python。声音克隆与人声分离使用两个隔离环境，模型和缓存都位于本目录的忽略目录中：

```powershell
pnpm setup:cuda
pnpm benchmark:overnight
```

所有持久 Python 包、模型与下载缓存都位于本 Demo 的 `.runtime` / `.models`。Windows 构建少数源码依赖时会在 D 盘根目录短暂使用 `D:\lc-voice-rendezvous-temp` 来规避路径长度限制；安装和赛马脚本无论成功或失败都会在退出时删除它。完整赛马输出在：

```text
results/local/
├── reference.wav
├── voxcpm15/
├── voxcpm2/
├── f5tts/
├── aggregate.json
└── validation.json
```

运行 `pnpm start` 后打开 `http://127.0.0.1:4178/web/results.html`，可以直接播放 one-shot、完整长程与开头/中间/末尾检查点，并按逐段真实耗时同屏模拟三个模型的后缀相遇过程。`validation.json` 自动拦截缺失、不可解码、时长不符、全静音和严重削波；详细人工评分标准见 [EVALUATION.md](./EVALUATION.md)。

## 产品化边界

Demo 已验证本地中英文转写、Codex 上下文双向翻译、UVR 人声/背景分离、纯人声参考、三模型 Cue 生成、后缀调度与浏览器双轨混音。它尚未实现最终视频导出或 Workbench 接入；现阶段输出的是可试听的算法与模型选型证据，不是可直接发布的视频成品。正式链路可在此基础上组合：

```text
字幕翻译 + 人声分离 → 按 Cue 从结尾组块 → 声音克隆 → 块落盘 → 更新连续后缀覆盖 → 背景轨与克隆人声混音播放
```
