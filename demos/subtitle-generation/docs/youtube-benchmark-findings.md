# YouTube 真实字幕基准结论

## 结论

首版仍选择 `whisper.cpp`，但运行档位需要区分：

- NVIDIA 推荐档：CUDA 12.4 + `large-v3-turbo-q5_0`。当前开发机处理 60 分钟视频，英文端到端估算约 67 秒，中文约 94 秒。
- 无 GPU 质量档：CPU + `small-q5_1`。60 分钟英文估算约 6.1 分钟，中文约 7.1 分钟；适合导入后后台预处理并缓存。
- CPU + `base`：英文尚可，中文长视频不可接受，不应作为产品默认档。
- SenseVoiceSmall Q8：CPU 中文 20 分钟约 41 秒、CER 4.09%，是很强的无 GPU 快速档；但英文 WER 19.02%，且当前裸运行时没有词级时间戳或渐进输出，不能直接替换 Whisper。
- Paraformer-zh Q8：CPU 中文 20 分钟约 39.9 秒、CER 7.79%；比 SenseVoice 快约 1 秒但错字更多，而且当前 GGUF 输出无标点、无段边界、无时间戳，不进入默认策略。
- 文本准确不代表 SRT 已经合格。所有模型都出现过跨越长静音的 Cue，最终产品需要额外的词级时间戳或 VAD 边界后处理。

## 环境与方法

- Windows，Intel Core i7-14700KF，32 GiB RAM，NVIDIA RTX 4090 D 24 GiB。
- Whisper CPU 线程数为 14，默认开启 Silero VAD。
- CUDA 与 CPU `base` 的每个中英文 1/5/20 分钟档位独立运行三次，报告中使用中位数并保留完整范围。
- CPU `small-q5_1` 是在 `base` 中文质量失败后增加的单次补测。
- 每次运行都重新规范化音频并启动独立 Whisper 进程；这不是字幕缓存命中数据。
- GPU 测试时 CS2 已退出，但保留视频壁纸和游戏平台等日常桌面负载，空闲 GPU 基线约 40%–50%。因此结果更接近日常使用，不是实验室空载峰值。
- CPU、RAM、GPU 与显存为整机采样；增量中位数可用于估算，但不能冒充进程级精确占用。

## SenseVoiceSmall CPU 快速档

运行时：`funasr-llama.cpp v0.1.9` Windows AVX2；模型：`sensevoice-small-q8`；中文每档 3 次。

| 语言 | 时长 | 转录中位数 | 端到端中位数 | CER/WER | RTF | RAM 峰值增量 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 中文 | 1 分钟 | 2.10 秒 | 2.29 秒 | CER 4.47% | 0.035 | 277 MiB |
| 中文 | 5 分钟 | 11.15 秒 | 11.46 秒 | CER 6.94% | 0.037 | 335 MiB |
| 中文 | 20 分钟 | 41.00 秒 | 41.77 秒 | CER 4.09% | 0.034 | 868 MiB |
| 英文 | 20 分钟 | 42.35 秒 | 43.31 秒 | WER 19.02% | 0.035 | 950 MiB |

耗时基本按媒体时长线性增长，中文 60 分钟估算约 122 秒。它在中文上比 Whisper CPU `small-q5_1` 快约 3.4 倍且 CER 略低，但仍会把“GPT”识别为“GBT”、“姚班”识别为“摇班”。英文准确率明显落后，不能作为通用模型。

FSMN-VAD 提供毫秒级语音段边界；SenseVoiceSmall 只返回每段文本。Demo 按标点拆成不超过 28 字符的 Cue，并在 VAD 段内按字符数分配时间，因此不会产生微碎片或 >7 秒 Cue，但该 IoU 只评价 VAD 覆盖，不能当成词级时间戳精度。裸运行时在整段处理完后才返回文本，20 分钟素材的首 Cue 也要等待约 41 秒。

## Paraformer-zh Q8 实验档

| 中文时长 | 转录耗时 | 端到端耗时 | CER | RTF |
| --- | ---: | ---: | ---: | ---: |
| 1 分钟 | 2.00 秒 | 2.19 秒 | 5.15% | 0.033 |
| 5 分钟 | 10.04 秒 | 10.38 秒 | 11.22% | 0.033 |
| 20 分钟 | 39.91 秒 | 40.72 秒 | 7.79% | 0.033 |

每个时长运行三次并取中位数；1 分钟三次输出逐字一致。Paraformer 比 SenseVoiceSmall 略快，但质量差距明显。模型全文只在结束时一次返回，且没有标点和可观测的 VAD 段文本边界。报告中的时间覆盖 IoU 来自 FSMN-VAD，Cue 文本则按全局语音时长和固定字数近似切分；这份 SRT 用来证明当前端口不适合字幕，而不是产品候选产物。

原始 Paraformer 模型支持 CIF 对齐，完整 FunASR 还可组合标点模型；这些能力没有出现在本次单文件 GGUF CLI 中。若未来为热词、标点或精确时间戳选择完整 ONNX/Python 管线，必须重新测安装体积、冷启动、首 Cue 和 CER，不能沿用本表结论。

## SRT 质量问题

文本错误率之外，还要单独验收字幕时间轴：

- CUDA 英文 1 分钟 WER 只有 1.49%，但存在一条 13.8 秒 Cue 跨过约 11 秒静音，时间覆盖 IoU 只有 79.1%。
- 输入长度变化会改变同一前缀的分段结果；不能假设“先生成前 5 分钟，再生成完整视频”会得到完全相同的 Cue 边界。
- CPU `base` 的中文长视频不仅错字多，还会把多个句子合并成长 Cue。

进入主应用前应验证 `--output-json-full` 的词级时间戳，或利用 VAD 语音区间钳制 Cue 起止时间。最终 SRT 需要经过独立结构校验：时间递增、无重叠、单 Cue 时长、每行长度和阅读速度。

## 初步硬件建议

- CUDA 推荐档：实测模型额外占用约 1.25 GiB 显存；考虑 Electron、视频解码和其他桌面程序，首版建议至少保证 4 GiB 可用显存，8 GiB 总显存更稳妥。该最低值仍需在真实 8 GiB 设备上复测。
- CPU 质量档：当前整机 RAM 增量约 0.5–1.6 GiB。建议 8 GiB RAM 作为最低运行条件，16 GiB 更适合同时播放视频和运行应用；仍需在低配机器验证。
- 安装体积：CPU `base` 约 162 MiB，CPU `small-q5_1` 约 202 MiB，CUDA 高质量档约 1.68 GiB。
